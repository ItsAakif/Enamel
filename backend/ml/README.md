# No-show prediction pipeline (T131)

A conventional, reproducible machine-learning lifecycle for a single assistive
signal: the probability that a booked appointment will be a no-show.

> **Disclosure.** This model is trained on **synthetic data** generated by
> `ml.no_show.dataset`. It is an experimental, assistive signal only. It is
> **not clinically validated** and it is not a clinical judgement; there is no
> clinical-validity claim anywhere in this repository, the metrics document or
> the inference API. Any UI that shows a score must label it
> "experimental, synthetic-trained, assistive".

## Layout

```
backend/ml/no_show/config.py     fixed knobs: seed, sizes, feature order, thresholds
backend/ml/no_show/features.py   the documented booking-time feature registry
backend/ml/no_show/dataset.py    synthetic generator + dataset hashing
backend/ml/no_show/evaluate.py   metrics, calibration bins, subgroup errors
backend/ml/no_show/train.py      leakage-safe split, baseline, candidate, gate
backend/ml/no_show/registry.py   artifact/metrics persistence + model registry
backend/scripts/train_noshow.py  CLI entry point
backend/apps/ml/                 registry + inference API (Django)
```

## Running

```
cd backend
..\.venv\Scripts\python.exe scripts\train_noshow.py --dataset synthetic --seed 42 --out artifacts/ml
..\.venv\Scripts\python.exe scripts\train_noshow.py --dataset synthetic --seed 42 --out artifacts/ml --check
```

The first command writes `artifacts/ml/noshow_metrics.json` and a `joblib`
artifact, and registers a `NoShowModel` + `TrainingRun` row. The second
re-runs the pipeline, recomputes the metrics hash and exits `0` only when it is
identical to the stored one. It writes nothing.

## Pipeline

1. **Dataset.** A fixed logistic process seeded by `--seed` produces at least
   1,000 appointments across a synthetic patient cohort. The generator targets
   an 18% no-show rate; the *measured* rate is recorded in the metrics
   document. Two documented interaction terms make the process non-additive so
   a tree model has real signal to find.
2. **Split.** `GroupShuffleSplit` by patient (`seed=42`) into
   `fit` / `validation` / `holdout`. Every pair is asserted patient-disjoint;
   a leak raises `SplitLeakageError`. A secondary chronological holdout checks
   that the model also generalises forward in time.
3. **Baseline.** Prior-probability (`DummyClassifier(strategy="prior")`) and
   logistic regression on standardised features.
4. **Candidate.** `HistGradientBoostingClassifier` wrapped in
   `CalibratedClassifierCV(method="isotonic", cv=3)`.
5. **Threshold.** Chosen on the *validation* slice by maximum F1.
6. **Activation gate.** The candidate is activated only when its holdout ROC
   AUC is not lower, and its holdout Brier score is not higher, than the
   logistic baseline. Otherwise it is rejected automatically and registered as
   a `candidate` (never activated).

## Features (known at booking time only)

Every feature is documented in `features.py` with the reason it is legitimate.
No feature uses information recorded after booking. The two riskiest --
`prior_no_show_count` and `prior_no_show_rate` -- are computed over strictly
earlier appointments and are pinned by the future-data guard test.

| feature | kind | reason (short) |
|---|---|---|
| `lead_time_days` | numeric | Days between booking and start; fixed at booking. |
| `hour_of_day` | numeric | Slot hour; chosen at booking. |
| `weekday` | numeric | Slot weekday; chosen at booking. |
| `appointment_type` | categorical | Service code; chosen at booking. |
| `provider_tenure_days` | numeric | Provider row age at booking; no later outcome. |
| `prior_no_show_count` | numeric | Earlier no-shows only; time-ordered history. |
| `prior_no_show_rate` | numeric | Normalised earlier history. |
| `prior_cancellations` | numeric | Earlier cancellations only. |
| `prior_visits` | numeric | Earlier completed visits only. |
| `patient_age_band` | categorical | Date of birth at booking; immutable. |
| `source` | categorical | Booking channel; recorded at creation. |
| `insurance_self_pay` | categorical | Payment route decided at booking. |
| `reminder_consent` | boolean | Consent record written before the visit. |
| `distance_band` | categorical | Static geography at booking. |
| `is_new_patient` | boolean | Cold-start flag from booking-time history. |

## Metric definitions

* **ROC AUC** -- probability that a random positive is ranked above a random
  negative. Threshold-free.
* **PR AUC** -- average precision; more informative than ROC AUC when positives
  are rare.
* **Brier score** -- mean squared error of the probability. Lower is better;
  this is what calibration improves.
* **Precision / recall / F1** -- computed at the chosen threshold.
* **Confusion matrix** -- counts of true/false positives/negatives at the
  threshold.
* **Calibration bins** -- ten equal-width probability bins; each reports its
  count, mean predicted probability and observed rate. `calibration_error` is
  the count-weighted mean absolute gap between the two.
* **Subgroup analysis** -- the same error metrics per `appointment_type`,
  `source` and `lead_time_band`. A subgroup with one observed class reports
  `roc_auc: null` with a note, never `NaN`.
* **Feature importance** -- global permutation importance (ROC AUC), ordered
  most-important first. The inference API surfaces these as `factors` and
  labels the method explicitly; they are a *global* explanation, not a
  per-prediction attribution.

## Reproduction contract

`metrics_hash` is the SHA-256 of the reproducible part of the metrics document
(everything except `trained_at`, `git_sha` and the artifact path). A fixed
`--seed` and dataset hash must produce an identical `metrics_hash`; `--check`
enforces it and CI fails otherwise. `git_sha` falls back to `unknown` when git
is unavailable.

## Inference

```
GET  /api/v1/ml/no-show/models/
POST /api/v1/ml/no-show/predict/   {"appointment_id": "...", "features": {...}}
```

The prediction response carries `probability`, `threshold`, `decision`,
`model_version`, `factors`, `factors_method`, `synthetic_data` and the
disclosure string. An incomplete feature vector is a `422` that lists every
missing feature; the API never silently imputes. A retired model is unreachable
for new predictions, but its existing `Prediction` rows keep their
`model_version` string and stay readable.

`insurance_self_pay` and `distance_band` are not persisted by any clinic model
today, so the caller supplies them via the optional `features` map; until they
are supplied the request is a `422`. This is deliberate: the alternative is a
silent default, which the spec forbids.

## Out of scope

Deep models, uplift/causal analysis, automated overbooking, a live retraining
scheduler, real-world usefulness (that needs real data).
